Introduction

Introduction

Problems identified and solutions proposed

🔴 Problems We Identified

  • Students and professionals have no centralized system to track daily routines, activities, habits, and tasks together.

  • Users cannot see how their time is distributed across categories (work, health, education, etc.).

  • Developed rule-based AI suggestions that give personalized improvement tips.
  • Built habit streak tracking with leaderboard and completion rate analysis.

Problem Identification

Infrequent Problems

Infrequent Problems & Solutions

Edge cases and uncommon issues we identified and resolved

ProblemHow We Solved It
Duplicate habit logs — A user could accidentally mark a habit as "done" twice on the same day, creating duplicate records.Added a UNIQUE(habit_id, date) constraint in the database. PostgreSQL now rejects any duplicate entry for the same habit on the same date.
Streak calculation breaks — If a user misses one day, the streak counter was sometimes off by one due to timezone differences.Used Django's timezone.localdate() instead of datetime.date.today() to ensure the streak counts align with the user's actual local date.
Productivity score out of range — Users could manually submit scores above 10 or below 1 through browser developer tools.Added Django validators MinValueValidator(1) and MaxValueValidator(10) at the model level, so invalid values are rejected server-side.
Cross-user data access — A user could theoretically access another user's data by modifying the URL (e.g., /routine/edit/5/).All views filter by user=request.user and return a 404 if the record doesn't belong to the logged-in user.
Chart.js empty data crash — When a new user with no data visits the reports page, Chart.js threw errors trying to render empty datasets.Added conditional checks: if no data exists, a "No data available yet" message is shown instead of rendering the chart.
CSRF token missing on AJAX — Toggle buttons (habit done/undone) initially caused 403 Forbidden errors.Added {% csrf_token %} to all POST forms and used proper form submission instead of AJAX for simplicity.

Database Schema

Complete Database Schema

7 tables — all normalized to 3NF

TableColumnsKey Constraints
auth_userid, username, password, email, first_name, last_namePK(id), UNIQUE(username)
accounts_userprofileid, user_id, profile_picture, bioPK(id), FK(user_id) → User, UNIQUE, 1:1
tracker_routineid, user_id, title, category, priority, start_time, end_time, is_completedPK(id), FK(user_id) ON DELETE CASCADE
tracker_activityid, user_id, title, description, category, date, start_time, end_time, status, mood, productivity_scorePK(id), FK(user_id) ON DELETE CASCADE, CHECK(1≤score≤10)
tracker_habitid, user_id, name, habit_type, streak, created_atPK(id), FK(user_id) ON DELETE CASCADE
tracker_habitlogid, habit_id, date, is_completedPK(id), FK(habit_id) ON DELETE CASCADE, UNIQUE(habit_id, date)
tracker_todoid, user_id, title, priority, is_completed, due_datePK(id), FK(user_id) ON DELETE CASCADE, due_date NULLABLE

Data Analysis

Data Analysis

How we analyze user data to provide valuable insights

📈

Productivity Trends

We calculate the average productivity score per day using SQL AVG(). Users can see which days they are most/least productive over the past 7 or 30 days.

🕐

Time Distribution by Category

We compute total hours per category (Work, Health, Education, Leisure, Social Media). A doughnut chart shows where the user spends the most time.

🔥

Habit Completion Analysis

We track 30-day completion rates per habit and rank them in a leaderboard. Users can see which habits they're consistent with and which need improvement.

🏆

Best & Worst Day Detection

The system identifies the user's most productive day and least productive day of the week, helping them optimize their schedule.

⚠️

Overdue Task Detection

We query Todo.objects.filter(is_completed=False, due_date__lt=today) to find tasks past their deadline and alert the user immediately.

⏱️

Work-Life Balance Check

We calculate average daily working hours. If it exceeds 10 hours, we warn about overwork. If below 2 hours, we suggest more focus time.
